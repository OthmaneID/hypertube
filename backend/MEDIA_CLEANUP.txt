HYPERTUBE - AUTOMATIC CLEANUP OF DOWNLOADED TORRENTS AND SUBTITLES
===================================================================

What it does
------------
Video files downloaded through torrents and subtitle files are kept on disk so
that a second viewer doesn't download them again. Anything nobody has watched
for 7 days is now deleted automatically. A video that is playing at the moment
the cleanup runs is never deleted.


Where the files live
--------------------
  backend/uploads/torrent/      torrent data (TORRENT_SAVE_PATH in services/Torrents.py)
      <Torrent Name>/...          a multi-file torrent is saved in its own folder
      <File Name>.mkv             a single-file torrent is saved directly here
      .<info-hash>.parts          libtorrent's "part file": pieces of files we did
                                  not ask for (other episodes of a season pack)
                                  that share a piece with a file we did ask for

  backend/uploads/subtitles/    WebVTT files (SUBTITLES_DIR in services/Subtitles.py)
      tt1234567_en_<id>.vtt       movie subtitle
      tt1234567_s1e2_fr_<id>.vtt  episode subtitle


Files involved
--------------
  config.py                       media_retention_days (default 7) and
                                  cleanup_interval_hours (default 6)
  models/CachedTorrentFile.py     table "cached_torrent_files" (one row per
                                  streamed file of a torrent)
  models/__init__.py              imports CachedTorrentFile so that
                                  Base.metadata.create_all() creates the table
  services/Torrents.py            records when a file is used, and which streams
                                  are playing right now
  services/Subtitles.py           refreshes the date of a subtitle when it is reused
  services/Cleanup.py             the cleanup job itself
  app.py                          starts the job in lifespan() and stops it on shutdown


1. Remembering when a torrent file was last used
------------------------------------------------
Each time a video is opened, open_stream_file() in services/Torrents.py calls
record_file_access(). This runs for both GET /torrent/stream/{hash} and
GET /torrent/stream/{hash}/info.

record_file_access() writes one row in cached_torrent_files:

    info_hash         the torrent hash from the URL
    file_idx          index of the video inside the torrent
    relative_path     path of the file inside uploads/torrent
                      (libtorrent's files.file_path(idx))
    size              file size in bytes
    last_accessed_at  now

It is an "upsert" (INSERT ... ON CONFLICT (info_hash, file_idx) DO UPDATE), so
watching the same file again only refreshes last_accessed_at; there is never
more than one row per file. It runs in a thread (asyncio.to_thread) with its
own DB session so the event loop is not blocked.


2. Knowing which videos are playing right now
---------------------------------------------
last_accessed_at is only written when a stream starts. A 3-hour movie started
6 days 23 hours ago would otherwise look expired while someone is watching it.

So Torrents.py also keeps an in-memory counter:

    open_streams = { info_hash: number of responses currently sending data }

Every streaming response goes through track_stream(hash, generator), an async
generator wrapper that:
  - increments open_streams[hash] when the first chunk is requested,
  - decrements it in a `finally`, which also runs when the browser disconnects,
  - explicitly calls generator.aclose() on the wrapped generator. Closing the
    wrapper does not close the inner generator by itself, and the inner
    generator's `finally` is what stops ffmpeg.

It wraps both kinds of responses:
  - serve_range(): direct mp4/webm playback, plus the internal requests ffmpeg
    makes to read the torrent file
  - stream_from_source(): the ffmpeg transcoded output


3. Remembering when a subtitle was last used
--------------------------------------------
No table is needed for subtitles: the file's modification time (mtime) is used
as its "last used" date.
  - A newly downloaded subtitle gets mtime = now when it is written.
  - When a cached subtitle is reused, resolve_language() in Subtitles.py calls
    touch_cached(), which does os.utime(path) to set its mtime to now.
The Watch page asks for subtitles every time it opens, so watching a movie
always refreshes its subtitles.


4. The cleanup job (services/Cleanup.py)
----------------------------------------
app.py starts cleanup_loop() as a background asyncio task when the server
starts and cancels it on shutdown. The loop runs run_cleanup() immediately, then
every cleanup_interval_hours. Any error is logged and the loop keeps going.

run_cleanup() does five steps:

  Step 1 - claim expired torrent rows   (thread: claim_expired_torrents)
    One SQL statement:
        DELETE FROM cached_torrent_files
        WHERE last_accessed_at < now - retention
          AND info_hash NOT IN (<hashes currently streaming>)
        RETURNING info_hash, relative_path
    The rows are deleted BEFORE the files. If someone starts the movie again at
    that moment, their upsert refreshes last_accessed_at, the row no longer
    matches the WHERE clause, and its files are kept.
    It also notes, for each hash, whether other files of the same torrent still
    have rows (for example another episode of the same season pack watched
    recently). That decides whether the .parts file can be deleted.

  Step 2 - stop libtorrent from using those torrents   (event loop)
    For each claimed hash:
      - if open_streams says it started playing in the meantime, skip it;
      - if it is in active_torrents, call drop_torrent(), which removes it from
        the libtorrent session and from the in-memory dicts.

  Step 3 - delete the files   (thread: delete_torrent_files)
    - delete uploads/torrent/<relative_path>
    - delete the parent folders that are now empty (stops at the first folder
      that still contains something)
    - delete uploads/torrent/.<hash>.parts only if no file of that torrent has
      a row left
    Every path is resolved with os.path.realpath() and must be inside
    uploads/torrent, so a bad relative_path can never delete anything else.

  Step 4 - orphan sweep   (thread: sweep_orphans)
    Removes files that have no row at all, for example:
      - downloads made before this feature existed,
      - a torrent whose metadata arrived but which was never played.
    For each top-level entry of uploads/torrent:
      - skip it if a row references it (first folder of relative_path), or if
        it is a .<hash>.parts file of a hash that has rows;
      - skip torrents currently loaded in libtorrent;
      - otherwise delete it if its newest file is older than the retention
        period. For a folder, the age comes from the newest file inside it; the
        folder's own mtime only counts when it is empty.

  Step 5 - subtitles   (thread: cleanup_subtitles)
    Deletes every *.vtt in uploads/subtitles whose mtime is older than the
    retention period.

Threading rule: active_torrents, wanted_files, probe_cache and open_streams are
read and changed by the streaming code on the asyncio event loop. Only the
event loop touches them: run_cleanup() reads or updates them between the thread
calls and passes plain copies (sets of hashes and names) to the threads. The database
and disk work runs in threads with asyncio.to_thread so the server keeps
streaming during a cleanup.

Each run logs what it removed, for example:
    [cleanup] deleted 2 unused torrent(s), freed 3400 MB
    [cleanup] deleted 1 untracked torrent entry, freed 120 MB
    [cleanup] deleted 5 unused subtitle file(s)


Configuration
-------------
Both settings come from config.py and can be overridden in .env (pydantic
settings, case insensitive):

    MEDIA_RETENTION_DAYS=7      delete what has not been used for this long
    CLEANUP_INTERVAL_HOURS=6    how often the job runs

Both accept decimals (for example 0.5).


How to test it
--------------
WARNING: with MEDIA_RETENTION_DAYS=0, everything that is not playing right
now is deleted on the next run, including your downloaded movies.

  1. In .env set MEDIA_RETENTION_DAYS=0 and CLEANUP_INTERVAL_HOURS=0.02
     (about one minute), then restart the backend container.
  2. Start a movie and keep it playing.
  3. Watch the logs:  docker logs -f backend | grep cleanup
  4. After a run: files of torrents that are not playing are gone from
     uploads/torrent, old .vtt files are gone, and the playing movie still
     plays and still has its files.
  5. Check the table:
        docker exec postgres psql -U <user> -d <db> -c "SELECT * FROM cached_torrent_files;"
  6. Restore the two values in .env.


Limitations / things to know
----------------------------
- open_streams lives in the memory of one process. The backend runs as a
  single uvicorn process today. If it is ever started with several workers,
  each worker would run its own cleanup and would not see the streams of the
  other workers, so it could delete a file another worker is streaming. With
  several workers, the job should run in only one of them (or in a separate
  process), and "currently streaming" would need to be shared (for example in
  Redis).
- When the backend restarts, libtorrent forgets its torrents but the files and
  rows stay. Expired rows are cleaned normally; untracked files are handled by
  the orphan sweep.
- A subtitle could be deleted in the short moment between the API returning
  its URL and the browser downloading it, only if it had not been used for 7
  days just before. The next page load downloads it again.
